# Camera 24 FPS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Set local MP4 recording and WebRTC camera forwarding to approximately 24 FPS with no changes to PLC or DXF behavior.

**Architecture:** Reuse the existing `IntervalGate` timing path. Only the two camera timing constants change; existing single-flight gates preserve responsiveness by dropping busy frames rather than queuing them.

**Tech Stack:** .NET Framework 4.8, C#, WPF, AForge camera capture, Accord/FFmpeg MP4 writer, SIPSorcery WebRTC.

## Global Constraints

- Keep MP4 bitrate at `2000000`.
- Keep WebRTC stream width cap at `640` px and target bitrate at `1000` Kbps.
- Do not modify PLC, DXF, G-code, or WebRTC signaling behavior.
- Use `42` ms as the integer timing target for both camera paths.
